# ERP-i18n-AI-Guidelines

## Purpose

* Defines how user-visible text is externalized, stored, and accessed in the ERP.

## Scope

* All user-visible output: UI labels, error messages, tooltips, dialogs, print templates.
* Out of scope: internal logging (`213-logging.md`), database identifiers, technical configuration keys.

## Mandatory Rules

### 1. No Hardcoded User-Visible Text
* MUST NOT put visible labels, button text, or messages directly into Java code; all user-visible text comes from resource bundles.
    * *Reason:* Hardcoded text cannot be translated.

### 2. Legacy Key Strings in Java Are Not Display Text
* Arguments to `getText(...)` are often **legacy bundle keys** (e.g. `Fmt_Etikett`) — identifiers, not the wording shown to users.
* MUST look the key up in the default bundle (German) and every existing `<bundle>_<lang>.properties` (`_en`, `_fr`, `_nl`, `_zh`, …) — NEVER infer text from the key name.
* When migrating to structured keys, MUST copy existing values from the bundles. If a language file has no entry, add the new key with an **empty value** — do not invent a translation.
    * *Reason:* Key names are abbreviated/technical; inferring text from them produces wrong customer-facing strings.

### 3. New Keys Ship German-Only
* The default bundle holds German. Every other locale, English included, is produced by an external translation firm.
* A new key gets its German value in the default bundle and the same key with an **empty value** in **every** other locale bundle. MUST NOT self-translate any locale, `_en` included.
* MUST NOT use another language's text as a placeholder value. A non-empty value in `<bundle>_<lang>.properties` MUST be in `<lang>`.
    * *Reason:* An empty value falls back to German until the firm's pass. A guessed or wrong-language value is silently wrong and detected by nothing.

### 4. Text Access
* MUST use `getText("key", args...)` with placeholders `{0}`, `{1}` for dynamic values; MUST NOT concatenate translated fragments manually.
    * *Reason:* Manual concatenation breaks word order across languages.

## Do / Don't Examples

### Do
```java
String msg = getText("common.save.success.message", entityName);
```

### Don't
```java
button.setText("Speichern");      // WRONG — bypasses translation
showError("Fehler: " + id);       // WRONG — hardcoded + concatenation
```

## Review Checklist

* [ ] **For the keys this change touches**, diff every sibling `<bundle>_<lang>.properties` against the default: key present in each, still sorted, every non-empty value in its own language? The bundles are not at full parity historically, so never sweep untouched keys.
