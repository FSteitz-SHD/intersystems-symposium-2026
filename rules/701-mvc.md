# ERP-MVC-AI-Guidelines

## Purpose

* Defines how to generate, modify, and review ERP client code using the in-house MVC framework: wiring, lifecycle, model binding, action wiring.

## Scope

* Client MVC code: controllers, binding views/models, lifecycle.
* Out of scope: server-side web MVC; general Swing code outside the MVC framework.

## Mandatory Rules

### Dependency Injection and Wiring

* MUST assume controller creation and lifecycle are framework-managed; MUST NOT instantiate controllers with `new`.
    * *Reason:* Controllers must be container-managed to receive their own dependencies.
* MUST inject sub-controllers with `@Inject` as fields in the parent controller.

### Lifecycle Usage

* MUST place normal controller setup in the parameterless `init()` (runs after view, model, and sub-controllers are injected).
* MUST explicitly close injected sub-controllers that own disposable resources (dialogs, embedded views) from the parent's `onClose()`.
    * *Reason:* Init is cascaded by the framework, teardown is not — an injected child leaks its resources on close unless the parent releases it.

### View Binding

* MUST use declarative binding in the view's `initBinding(binder)` when the view is a binding view.
* MUST expose every bound model property via a `public` getter and setter; MUST NOT hide them behind `protected`/`private` accessors.
    * *Reason:* The binding framework reads properties via reflection — a private getter compiles and fails at runtime.

### Action Wiring

* MUST wire buttons and menu items through the model (model declares an empty `onXxx()` hook, view binds the widget to it, controller listens on the model).
* MUST NOT call `view.getBtnXxx().addActionListener(...)` directly from the controller.
    * *Reason:* The model is the contract surface; binding keeps wiring inspectable and survives widget replacement.

## Do / Don't Examples

### Do
```java
// View: declarative binding
binder.bind(CustomerModel::getName, CustomerModel::setName).to(txtName);

// Model
public String getName() { return name; }
```

### Don't
```java
private OrdersCtrl ordersCtrl = new OrdersCtrl();   // WRONG — breaks DI and lifecycle
private String getName() { return name; }          // WRONG — compiles, fails at runtime in the binder
```

## Review Checklist

* [ ] Bound properties `public`; binding in `initBinding(...)`?
* [ ] Disposable sub-controllers closed from the parent's `onClose()`?
